# Manifest format

An artifact directory contains a JSON-syntax `vlips.yaml` configuration and a
UTF-8 `segments.csv`. L3/L4 additionally use pipeline and transition evidence.
Generate a valid skeleton with:

```bash
vlips init my-split --level L2
```

The bundled synthetic example is under `examples/minimal/`.

## `segments.csv`

The header is:

```text
segment_id,physical_emitter_id,acquisition_id,source_file_id,sample_start,sample_end,model_version,role,usage,evidence_level
```

| Column | Meaning |
|---|---|
| `segment_id` | Stable, unique identifier for this manifest row. |
| `physical_emitter_id` | Stable identifier for the physical transmitting device. |
| `acquisition_id` | Stable identifier for the data-collection event or recording session. |
| `source_file_id` | Stable logical or content-derived identifier for the source file. |
| `sample_start` | Zero-based inclusive start of the declared source interval. |
| `sample_end` | Exclusive end of the declared source interval; must exceed `sample_start`. |
| `model_version` | Version of the decision system to which the role assignment is bound. |
| `role` | Data role declared by the artifact policy. |
| `usage` | Purpose for which the segment may be consumed. |
| `evidence_level` | Highest lineage field for which this row has supporting evidence. |

Do not put absolute filesystem paths in an identifier column. Identifiers should
be opaque, stable, non-secret values such as `src-001` or a separately managed
content digest. A different string is meaningful only when it identifies a
genuinely different entity.

CSV escaping follows standard RFC 4180 conventions. Empty identifiers and
malformed numeric intervals are not silently repaired.

## Roles and policy

Roles express how a segment may influence the evaluated system. Use the values
generated by `vlips init` and keep the role policy in `vlips.yaml` aligned with
your evaluation design. Changing a role name does not remove a dependency; the
manifest must faithfully represent actual use.

Typical uses include training/enrollment, calibration or selection, and final
query evaluation. A nominally unknown query must not share a prohibited source,
acquisition, or physical emitter with upstream roles at the corresponding
level.

## Evidence levels on rows

`evidence_level` records what can be substantiated for the row. Accepted values
are `resolved`, `verified`, `complete`, `unresolved`, or an explicit `L0`--`L4`
cap. It is not an override. A row marked L3 must contain meaningful source, acquisition, and
physical-emitter identifiers, and those identifiers must be backed by the
upstream provenance process. Unresolved row evidence limits the highest level
that can be proved.

## Auxiliary L3/L4 evidence

`pipeline_dependencies.json` represents pipeline reachability and version
binding. `query_transitions.csv` represents the fresh-query transitions needed
for L4 after query-consuming updates; each applicable row must bind different
model versions and affirm `fresh_relative_to_previous_versions` with
`true`, `yes`, or `1`. Use `vlips init PATH --level L4` or
`vlips schema export` for the exact
schema supported by the installed version.

The tool treats these files as declarations to validate. It does not instrument
a running model pipeline or discover hidden state automatically.

## Privacy

Before publishing a manifest:

1. replace device serial numbers and personal identifiers with stable opaque
   IDs;
2. remove absolute paths, hostnames, bucket names, and credentials;
3. verify that IDs cannot be trivially joined to a private inventory;
4. keep raw RF data and labels outside the repository;
5. review the staged files independently for secrets and redistribution rights.
